## Known deviations / incidents (full disclosure)

1. The first C3 gather implementation selected stream-OR-bounce
   instead of stream-PLUS-bounce for wall-adjacent receivers; found
   via a standalone Taichi scatter replay (2.4e-7 agreement with the
   solver) and fixed before any conclusion was drawn; the C1
   diagnosis (no solids) was unaffected; dx_C3/bg_C3 re-run after the
   fix (v2 logs).
2. A solver edit made while the first candidate batch was still
   running invalidated 8 arms (exit 1); all were re-run cleanly in
   `run_retry_a2_batch.sh` (the arms that completed before the edit —
   the C1X+A1 candidate runs — were produced by the pre-edit code and
   are bit-consistent with the retry since the A0/A1 code paths are
   arithmetic-identical in both versions).
3. GPU run-to-run nondeterminism (f32 atomic ordering) is documented
   by a same-code double run (`SMOKE_A0_repro`/`SMOKE_A0_repro2`,
   since removed) and by the base 60k rerun vs the committed base
   (2% slope band); all gate conclusions are far outside this band.
4. The first A2-pipeline implementation crashed (Taichi static-branch
   scoping: `g_r` defined in one `ti.static` branch, used in another);
   fixed by the dtype attribute + self-contained closure branches.
